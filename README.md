# نسخة Netlify

ابدأ بملف NETLIFY-SETUP.md لتجهيز متغيرات Firebase ومفتاح التشفير والنشر. هذه النسخة لا تستخدم Netlify Blobs.

# إدارة أسعار Shopify — تطبيق محلي

واجهة عربية بـ Next.js وTypeScript لإدارة أسعار SKUs محددة. كل العمليات تمر بمعاينة، ولا يتغير أي منتج غير مدرج. لا يحتاج التطبيق استضافة أو Cloudflare.

## التشغيل

للتجربة الآن استخدم الحساب المؤقت الموضح في نهاية هذا الملف، بدون إعداد Firebase. ثبّت Node.js 24، ثم افتح Terminal داخل مجلد المشروع:

```sh
npm install
npm run dev
```

افتح http://127.0.0.1:3000. السيرفر يستمع على جهازك فقط.

للتشغيل بوضع الإنتاج محليًا:

```sh
npm run build
npm start
```

## ربط متجر Shopify

أنشئ تطبيقًا في Shopify Dev Dashboard، وفعّل `read_products` و`write_products`، ثم ثبّته على المتجر واعتمد الصلاحيات. أدخل Client ID وClient Secret ودومين `your-store.myshopify.com` في التطبيق المحلي.

توليد التوكن بطريقة `client_credentials` يحتاج أن يكون التطبيق والمتجر ضمن نفس مؤسسة Shopify. الدومين التجاري المخصص أو مفاتيح تطبيق غير مرتبط بالمتجر لا تكفي. متاجر العملاء خارج المؤسسة تحتاج إضافة OAuth، وهو غير مطبق هنا.

مرجع: https://shopify.dev/docs/apps/build/authentication-authorization/client-credentials-grant

## العمليات الخمس

| العملية | المدخلات | النتيجة |
| --- | --- | --- |
| تحديد سعر قبل وبعد / سعر بيع فقط | سعر قبل الخصم اختياري + سعر البيع النهائي | نفس الأسعار لكل SKUs؛ ترك قبل الخصم فارغًا يمسح سعر المقارنة الحالي |
| خصم بنسبة | نسبة الخصم + أساس الحساب | يحسب سعر البيع ويحفظ الأساس كسعر المقارنة |
| زيادة سعر البيع بنسبة | نسبة الزيادة فقط | يزيد سعر البيع الحالي لكل SKU مباشرة؛ لا يوجد حقل لسعر ثانٍ |
| إلغاء الخصم واسترجاع السعر الأصلي | SKUs فقط | يسترجع سعر المقارنة الأعلى إلى سعر البيع ويمسح سعر المقارنة |
| إضافة تاج | اسم تاج واحد + SKUs | يضيف التاج للمنتج الأساسي ويحافظ على التاجات الموجودة والأسعار |

### أمثلة

- **تحديد مباشر:** قبل 1000 وبعد 800 → Compare-at price = 1000 وPrice = 800.
- **سعر واحد:** قبل فارغ وبعد 900 → Price = 900 وCompare-at price فارغ، حتى لو كان موجودًا سابقًا.
- **خصم 20%:** أساس 1000 → قبل 1000 وبعد 800.
- **زيادة 20%:** SKU سعره الحالي 100 → سعر البيع الجديد 120. SKU آخر سعره 200 → سعر البيع الجديد 240. سعر المقارنة الموجود يظل كما هو إن كان أعلى من سعر البيع الجديد، وإلا يُمسح. لا تُنشأ قيمة مقارنة جديدة من الزيادة.
- **إلغاء الخصم:** قبل 1000 وبعد 800 → سعر بيع 1000 وسعر المقارنة فارغ.

السعر قبل الخصم، عندما يُستخدم، يجب أن يكون أكبر من سعر البيع النهائي. إذا لم يتحقق ذلك لأي SKU تُظهر المعاينة الخطأ ولا تعدّل هذا الصف. نسب العمليات بحد أقصى منزلتين عشريتين، والأسعار الثابتة يجب أن تناسب دقة عملة المتجر.

## سير العمل

1. اربط المتجر واختر العملية.
2. أدخل كل SKU في سطر أو افصل بفاصلة، حتى 500 SKU في الدفعة.
3. أدخل حقول العملية المطلوبة فقط.
4. اضغط «معاينة الأسعار». سترى سعر البيع الحالي وسعر المقارنة الحالي والجديد وسعر البيع الجديد وحالة كل صف.
5. راجع النتيجة ثم اضغط «تطبيق التغييرات». أبقِ الصفحة مفتوحة أثناء التنفيذ.
6. راجع نتائج الصفوف. فصل المتجر يتيح لك ربط متجر آخر.

تغيير العملية أو المدخلات يمسح المعاينة السابقة. الأسعار الثابتة موحدة على الدفعة؛ استخدم دفعات منفصلة لو لكل مجموعة أسعار مختلفة.

## قواعد التنفيذ

- المطابقة تامة وحساسة لحالة الأحرف. تحديث متغير لون/مقاس لا يغير المتغيرات الأخرى.
- تكرار SKU في الإدخال يُزال. تكراره على متغيرين في Shopify يمنع تحديثه.
- يُعاد فحص هوية المنتج وأسعاره قبل الكتابة. تغيير السعر بعد المعاينة يمنع التنفيذ. Shopify لا يقدم هنا معاملة ذرية مع الفحص؛ لا تشغّل محررات أسعار أخرى بالتزامن.
- كل صف مستقل؛ قد تنجح صفوف وتفشل أخرى. لا توجد إعادة محاولة تلقائية لطلبات الكتابة.
- انقطاع الاتصال وقت التنفيذ قد يحدث بعد تنفيذ Shopify بالفعل. راجع المتجر قبل إعادة المحاولة، خصوصًا في عمليات النسب المحسوبة من السعر الحالي.
- الحساب بوحدات العملة الصحيحة مع تقريب نصف الوحدة لأعلى.
- «خصم من السعر الأصلي» يستخدم سعر المقارنة إذا كان أعلى من سعر البيع، وإلا السعر الحالي. الخصم من الحالي يضيف خصمًا آخر عند معاينة وتطبيق دفعة جديدة.
- في الاسترجاع: سعر المقارنة الفارغ أو المساوي/الأقل من سعر البيع يُترك كما هو، ولا يتم اختراع سعر تاريخي.
- في التحديد المباشر، الصفوف المطابقة بالفعل لا تُكتب من جديد.
- التعديل لأسعار المتجر الأساسية، وليس قوائم Shopify Markets أو B2B. لا ينشئ Discount Codes. ظهور السعر المشطوب يعتمد على ثيم المتجر.

## بيانات الربط

بيانات Shopify محفوظة مشفّرة داخل Cookie محمية، ومفتاح التشفير في SESSION_ENCRYPTION_KEY على السيرفر. صلاحية الربط 24 ساعة كحد أقصى. الفصل يمسح الكوكي. لا نستخدم Blobs أو Firestore لحفظ بيانات الربط. راجع NETLIFY-SETUP.md للحدود وطريقة الإعداد.


## تسجيل الدخول وFirebase

مع إعداد Firebase، الدخول متاح بحساب Google أو البريد، لكن تشغيل أدوات Shopify يتطلب اشتراكًا شهريًا بـ10 دولارات اعتمده الأدمن ولم تنتهِ مدته. الأدمن وحده يستخدمه مجانًا. الدفع يدوي عبر إنستا باي 01126813849؛ المستخدم يبلغ بالدفع والأدمن يراجع التحويل ويضيف شهرًا. الطلبات تظهر فورًا داخل لوحة الأدمن المفتوحة. حدّد قيمة التحويل بالجنيه من تعليمات الدفع في اللوحة. اتبع **FIREBASE-SETUP.md** أولًا وانسخ **.env.example** إلى **.env.local**. عند عدم اكتمال هذه الإعدادات يتاح الحساب المحلي المؤقت الموضح أدناه، ما لم يتم تعطيله.

المفاتيح وتوكن Shopify تُشفّر داخل كوكي المتصفح، وجلسة الربط مقيدة بمستخدم Firebase نفسه. Firestore يحفظ سجل المعاينات والنتائج لكل مستخدم بدون بيانات الربط السرية. الحماية موجودة في الواجهة وطلبات السيرفر وقواعد قاعدة البيانات.

## إضافة تاج

اختَر «إضافة تاج للمنتجات»، وأدخل تاجًا واحدًا وقائمة SKUs ثم عاين وطبّق. Shopify يضع التاج على المنتج الأساسي المرتبط بالـSKU، وليس على المتغير وحده. الإضافة تستخدم tagsAdd حتى لا تمسح التاجات الموجودة، ولا تعدّل الأسعار. إذا كان التاج موجودًا يعتبر المطلوب متحققًا. تعدد SKUs التابعة لنفس المنتج لا يكرر كتابة التاج بعد التأكد من وجوده.

مرجع Shopify: https://shopify.dev/docs/api/admin-graphql/latest/mutations/tagsadd

## خانات النتائج النهائية

بعد الجدول توجد خانتان منفصلتان، كل منهما تحتوي SKUs فقط وزر نسخ:

- «حصل فيها خطأ أو لم تتم»: الأخطاء والصفوف التي ما زالت تنتظر التنفيذ، أو غير القابلة للعملية مثل استرجاع سعر لمنتج ليس عليه خصم.
- «لم يتم العثور عليها»: SKUs التي لم تُطابق أي متغير بشكل تام، سواء أثناء المعاينة أو إعادة الفحص قبل التنفيذ.

التاج الموجود أو الأسعار المطابقة بالفعل لا تُعتبر أخطاء ولا تظهر ضمن غير المكتمل. الأسباب التفصيلية في الجدول. النتائج المحفوظة السابقة متاحة من «سجل عملياتك في Firebase».


## الدخول المؤقت بدون Firebase

في النسخة الحالية، عند عدم اكتمال إعداد Firebase يظهر دخول محلي مؤقت:

- اسم المستخدم: `admin`
- الباسورد: `SkuLocal!8n4R27`

شغّل `npm install` ثم `npm run dev` وافتح http://127.0.0.1:3000. كل عمليات Shopify والمعاينة وخانات النتائج متاحة، لكن سجل Firestore غير متاح في الوضع المؤقت. بيانات Shopify تظل مطلوبة لربط المتجر.

الجلسة HttpOnly وصالحة 8 ساعات، وتنتهي عند تسجيل الخروج أو إيقاف السيرفر. يتم التحقق منها على السيرفر، والحساب متاح على localhost/127.0.0.1 فقط. عند اكتمال قيم Firebase الأربع يتوقف هذا الدخول تلقائيًا وتعود شاشة Firebase.

لإيقافه يدويًا ضع `LOCAL_TEMP_LOGIN=false` في .env.local. ولتغيير بياناته استخدم `LOCAL_TEMP_USER` و`LOCAL_TEMP_PASSWORD` ثم أعد تشغيل السيرفر. هذا الحساب للتشغيل المحلي المؤقت فقط؛ استخدم Firebase عند نقل التطبيق لاستضافة عامة.
